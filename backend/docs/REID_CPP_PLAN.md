# ReID / MTMC C++ 运行时实施方案

日期：2026-10-13。目标：保留现有推理，新增两个模块可选择的 C++ 特征提取核心，并用实测评价收益。

## 架构选择

采用 C++17 + ONNX Runtime CPU 的共享库，导出稳定 C ABI，Python 使用 ctypes 调用。与 pybind11 相比不绑定 Python ABI；与独立 HTTP/子进程服务相比避免图片编码、网络传输和进程间拷贝。保留 Flask、权限、数据库、检测器、跟踪器、跨镜关联策略和前端工作台。

原生核心负责 RGB/归一化/NCHW 转换、持久 ONNX 会话、推理、批处理输出检查。图片解码和双线性 resize 使用已有 OpenCV 原生实现，避免额外 OpenCV C++ SDK 依赖。输出保留原始模型向量，已有业务层继续 L2 归一化，保持模型空间及版本键不变。

运行时支持 `python`（原有路径、默认）、`cpp`（严格使用原生库，失败可见）、`auto`（尝试原生库，失败显式记录后回退原有路径）。不修改模型、不自动量化、不混合不同模型空间。C++ 会话按资产绝对路径、mtime_ns、size、线程配置缓存，使用有界 LRU。运行时 DLL 路径由服务端配置，不接受客户端任意库路径。

固定 batch=1 模型在 C++ 内逐项推理；动态 batch 模型使用模型批推理；固定 batch>1 暂不支持。输入限定单个 float32 NCHW、三通道、固定空间大小，输出限定首个 float32 embedding，每个样本独立。

## 实施顺序

1. 梳理所有业务模块的模型、设备、缓存、预处理、串并行链路和优化优先级，输出 `PROJECT_INFERENCE_OVERVIEW.md`。
2. 先写运行时选择、缺库、显式回退、模型空间保留、ABI 与真实 ONNX 一致性测试。
3. 实现 C ABI 原生核心及 CMake 构建，提供 Python 桥、批量提取和有界会话生命周期。
4. 独立 ReID 登记/识别/图库检索/录像检索接入运行时参数，前端提供全模块共享选择。
5. MTMC 配置接入 `reidRuntime`，强模型与 Youtu 共享原生核心，保留原有模型空间、预算、轨迹聚合、跨镜策略；实际 provider 和回退错误进入运行时状态。
6. 使用合成 ONNX 验证数值、固定/动态 batch、非连续裁剪、并发及错误；运行既有 ReID/MTMC 回归。
7. 提供基准脚本，记录冷加载、热推理 p50/p95、吞吐、余弦一致性及软硬件信息。可用真实权重时实测，未覆盖项明确标记，不承诺未经测量的速度倍率。

## 验收边界

两个功能模块的神经网络特征推理可由新 C++ 库执行；检测、跟踪、数据库及关联仍由现有服务编排。这是两个模块的 C++ 核心版本，非完整服务重写。速度受模型、设备、线程和并发影响，C++ 调用层本身不保证超过现有原生 OpenCV/ORT 算子。部署文档需列出构建依赖、启用、回退、诊断与基准命令。
