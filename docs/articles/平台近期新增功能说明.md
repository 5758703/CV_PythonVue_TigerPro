## 1.1 开放词汇检测（OmDet-Turbo）

- **模型键**：`omdet-turbo-swin-tiny`（HuggingFace `omlab/omdet-turbo-swin-tiny-hf`）
- **用法**：图像检测页选择该模型后填写「提示类别」（如 `person,car,dog`），按文本开放词汇出框
- **定位**：与固定类 YOLO 并存；适合临时类别、零样本演示，不替代实时主链路 YOLO

---

## 1.2 多模态定位（VLM-FO1）

- **模型键**：`vlm-fo1-3b`；依赖官方仓 `uploads/models/third_party/VLM-FO1` 与约 9GB 权重
- **用法**：图像检测页输入自然语言提示（如「红色安全帽」），引擎用 YOLO 低阈值候选框 + FO1 筛选 region
- **建议**：GPU；`pip install -r uploads/models/third_party/VLM-FO1/requirements.txt` 后在模型管理拉取权重

---

## 1.3 ASR · MOSS-Transcribe-Diarize

- **模型键**：`moss-transcribe-diarize-0p9b`
- **能力**：端到端多人说话人转写、时间戳；支持音/视频上传（视频经 ffmpeg 抽音）
- **前端**：`/ai/asr` 字幕预览、时间轴、导出 JSON / SRT / ASS
- **实现**：`services/moss_mtd.py` 内置推理辅助，不强制依赖 GitHub 包

## 2. 跨镜 MTMC 重识别（重点）

### 2.1 解决什么问题

单摄像头追踪只能保证「这一路」的 track_id。园区、楼宇、车场往往是多路 RTSP：人从门口走到走廊，车从入口到出口，业务要的是**跨镜头仍是同一个人/同一辆车**。MTMC（Multi-Target Multi-Camera）把局部轨迹聚合成全局 ID。

### 2.2 平台链路（简化）

1. **共享拉流**：多路只拉一次，供给检测与叠加，避免重复解码。  
2. **局部 Tracklet**：每相机内做检测 + 局部跟踪；货车等大目标漏跟时补 orphan 框。  
3. **人员强 ReID**：OSNet / CLIP-ReID 与 Youtu 并联；跨视角弱外观时用 HSV 颜色签名抬分。  
4. **车辆身份**：可靠车牌优先；视觉 ReID 用对侧相机原型（`crossProto`）；类别门控避免 truck↔car 误合。  
5. **三档门控**：ReID ≥ 确认阈值 → 自动合并；介于候选～确认 → 新建 Global 并记候选；低于候选 → 新建。  
6. **证据落库**：会话控制开启「证据落库」后，Tracklet / 候选对 / 证据边写入数据库，便于停会话后审计。  
7. **候选晋升**：在「Tracklet / 证据」Tab 对 pending 候选点晋升（合并）或驳回（保持分离）；需会话仍在运行。  
8. **呈现**：跨镜页每路 MJPEG 预览 + **当前帧检出列表**；监控墙填写会话 ID 后开启「AI 叠加」。

### 2.3 联调必读（近期修正）

- **重叠视野**（同街两侧几乎同时看到同一目标）：拓扑 **最短通行秒 = 0**，否则两侧全是 `new`、永不合并。  
- **多路必须时间对齐**：本地录像请同步/交错播放，不要先跑完一路再跑另一路。  
- **策略代码更新后重启 backend**，Associator 才在内存中生效。  
- **人工核对候选时请打开「证据落库」**，否则 DB 可能无 pending 记录，晋升/驳回依赖内存会话。

页内「操作说明」Tab 与 [`docs/mtmc-cross-camera-reid.md`](../mtmc-cross-camera-reid.md) 已按上述行为同步。

### 2.4 McByte++ 解耦优化

近期对关联策略做了工程化拆分：

- **短时粘性**：已绑定的轨迹优先保持，减少无意义 ID 抖动。  
- **新生才长时 ReID**：只有新轨迹才做高成本外观匹配，降低每帧提特征次数。  
- 可选 **BoT-SORT + CMC** 等局部跟踪增强，适配镜头抖动场景。

### 2.5 怎么验收

| 检查项 | 通过标准 |
|--------|----------|
| 会话启动 | `/api/ai/mtmc/sessions/start` 返回 sessionId |
| alive | 叠加前调用 alive，过期则回退普通流 |
| 人员跨镜 | 同人两路出现同一 global_id（或业务姓名） |
| 车辆 | 有牌片段以车牌键稳定；无牌不刷假新生；重叠视野同车同 Global |
| 证据落库 | 开启后 Tracklet / 候选表有库表记录；晋升后 Global 合并 |
| 监控墙 | AI 叠加有框/ID，关闭叠加不白屏 |

详细设计见 [`docs/mtmc-cross-camera-reid.md`](../mtmc-cross-camera-reid.md)。

## 3. 跌倒检测

### 3.1 能力要点

- **判定**：基于姿态关键点的多指标门控（非单纯「躺下框」），降低特写/低机位误报。  
- **输入**：图片、视频、摄像头实时。  
- **视频模式**：后端异步逐帧处理，产出标注视频 + 触发事件列表。  
- **告警**：告警中心支持 `fall_detection` 规则；结果视频可同步告警音。  
- **跟踪**：轻量跨帧跟踪，减少髋部掉检导致的 ID 乱跳。

### 3.2 使用建议

1. 先在 `/ai/fall` 用真实摔倒/蹲下/弯腰样本做冒烟。  
2. 再到「检测告警」配置跌倒规则与冷却时间，避免刷屏。  
3. 摄像头机位尽量覆盖全身；极端特写需单独验收。

## 4. 手势识别（数字 + 中国手语）

### 4.1 双通路

| 通路 | 技术 | 典型输出 |
|------|------|----------|
| 数字手势 | OpenCV Zoo MediaPipe 掌检 + 手部 21 点 | 0–5 / 手，双手可至 10；稳定后写入数字序列 |
| 中国手语 | YOLO 检测类 | 手语类别标签 |

支持**多选同跑**：同一画面同时开数字与手语，适合演示与无障碍交互原型。

### 4.2 入口

侧栏 **视觉识别 → 手势识别**（`/ai/handpose`），权限 `ai:handpose:*`。

## 5. 项目门户与双前端架构

| 应用 | 端口（开发） | 职责 |
|------|--------------|------|
| `frontend/frontend_home` | 5174 | 宣传、能力展示、按登录态跳转控制台 |
| `frontend/frontend_admin` | 5173 | RBAC 控制台、全部 AI 工作台 |

- 公开接口：`GET /api/portal/summary`、`GET /api/health`。  
- 登录态：控制台写入 `localStorage` + Cookie `tiger_ai_token`，门户跨端口可读。  
- 深链示例：`/login?redirect=/ai/fall`；控制台顶栏可回「项目门户」。

本机请统一使用 **localhost**，勿混用 `127.0.0.1`，以免 Cookie 域不一致。

## 8. 与既有能力的关系（避免重复建设）

| 既有模块 | 和新功能的关系 |
|----------|----------------|
| 图像检测 `/ai/image` | OmDet / VLM-FO1 与 YOLO 同页选型；开放词汇走提示类别/自然语言 |
| 语音 ASR `/ai/asr` | funasr 与 MOSS 并存；MOSS 侧重多人说话人 |
| 行人 ReID `/ai/reid` | 单镜/底库检索；MTMC 可并联其外观能力做跨镜 |
| 人脸 `/ai/face` | 近距识人；离岗、门禁仍用人脸；MTMC 不替代人脸 |
| 目标追踪 `/ai/track` | 单路场景（通用/车辆/离岗）；跨镜请用 MTMC |
| 检测告警 `/ai/alert` | 承接跌倒等规则事件 |
| 监控墙 `/camera/wall` | 消费 MTMC session 做 AI 叠加 |

选型口诀：**单路业务用追踪/人脸/ReID；跨路全局 ID 用 MTMC；临时类别用 OmDet；自然语言定位用 VLM-FO1；安全事件走告警。**

## 9. 建议试用路径（30 分钟）

1. 打开门户 http://localhost:5174 → 进入控制台。  
2. **模型管理**确认姿态 / 检测 / ReID / OmDet 或 MOSS 相关权重已拉取。  
3. `/ai/image` 试用 OmDet 提示类别或 VLM-FO1 自然语言（有 GPU 时）。  
4. `/ai/asr` 上传一段多人对话试转写与字幕导出。  
5. `/ai/fall` 跑一张图或一段短视频。  
6. `/ai/handpose` 开摄像头试数字手势。  
7. 用屏幕 RTSP 或两路测试流启动 `/ai/mtmc`（建议开「证据落库」），核对候选后到监控墙开叠加。  
8. 回到首页「热门场景」卡片，按入口复查一遍。
