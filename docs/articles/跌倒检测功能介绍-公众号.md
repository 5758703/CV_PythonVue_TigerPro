## 二、原理一句话：先看骨架，再判「像不像跌倒」

### 1. 姿态模型（看得见的人）

本页依赖 **姿态估计** 模型（YOLO-pose / RTMO / RTMPose 等），输出人体 **COCO-17 关键点**（肩、髋、踝、鼻等），并画出骨架。

若提示「暂无可用模型」，请到 **模型管理** 拉取并启用 `pose-estimation` / `wholebody-pose-estimation` 相关权重。

![1786776512030](C:\Users\ADMINI~1\AppData\Local\Temp\1786776512030.png)

### 2. 四指标综合打分（判得准一点）

规则引擎从关键点算出四类几何量（可单独加权开关）：

| 指标 | 含义（通俗） | 默认倾向 |
|------|--------------|----------|
| **躯干角** | 肩–髋连线相对竖直的倾斜 | 倾角过大 → 像躺/倒 |
| **质心速度** | 身体中心跨帧移动快慢 | 突然下坠 → 像摔倒过程 |
| **身高比** | 肩踝高度跨度相对躯干长度 | 变得「扁」→ 像卧地 |
| **头部高度** | 头部在画面中的相对高度 | 过低 → 像倒地 |

每个越线指标按权重得分，**总分达到「判定得分」** 才视为当帧疑似跌倒；再经 **连续帧确认** 与 **冷却时间**，才记一条正式告警事件。

默认思路（可改）：躯干 / 速度 / 身高比各 1 分，头部权重默认 0；**得分 ≥ 2** 才判当帧跌倒——避免「只是弯腰」就误报。

## 三、三种模式：图片 / 视频 / 摄像头

### 模式 1：图片（单帧演示）

适合截图对比、汇报材料：

1. 选 **姿态模型**，调 **置信度**（默认约 0.25）  
2. 打开 **记录事件**（需要落库时）  
3. **选择图片** → **开始检测**  
4. 看结果图：人数、疑似跌倒人数；右侧看是否触发告警  

图片模式按「独立单次判定」处理，适合静态样例；连续视频流那套「冷启动防误报」逻辑不按长视频同一套卡住你。

### 模式 2：本地视频（异步批处理）

适合回看监控片段、课堂演示：

1. 模式切 **视频** → **选择视频** → **开始检测**  
2. 看进度：`已处理帧 / 总帧`  
3. 完成后播放 **标注结果视频**，可 **下载**  
4. 右侧 **触发记录** 按秒展示，点击可跳到对应时刻  

统计区常见两项：

- **红框帧数**：合成视频里「该帧判定为跌倒」就会画红框  
- **触发次数**：受规则 **连续帧确认 + 冷却**（默认冷却约 60 秒）约束，**远少于红框帧数是正常的**，不是漏检

## 四、告警长什么样、记到哪里

命中后典型表现：

- 画面：**红色跌倒框** + 半透明面板文案（如 `FALL DETECTED`、`疑似跌倒 / 请立即查看`）  
- 事件标题示例：**「跌倒告警：检测到 N 人疑似跌倒」**  
- 建议话术：立即查看老人状态，确认意识与外伤；必要时急救，避免长时间卧地  

开启 **记录事件** 后，事件可进入平台告警体系（便于后续在告警中心排查）。

## 五、关键配置：到「检测告警」调四指标

路径：**人工智能 → 检测告警**（或平台中的告警规则管理页）→ 找到 **「跌倒检测告警」**（`fall-detection`）。

请确认：

1. 规则 **已启用**  
2. 按场景调阈值与权重  

常见可调项（名称以页面为准）：

| 配置项 | 作用 |
|--------|------|
| 躯干角阈值 | 倾斜到多少度算「躯干指标」命中 |
| 质心速度阈值 | 下坠多快算「速度指标」命中 |
| 身高比阈值 | 身体「压扁」到什么程度命中 |
| 头部高度比 | 头够不够低（默认可关闭权重） |
| 各指标权重 | 某指标是否计入、占多少分 |
| 判定得分 | 总分达到多少才算当帧跌倒（建议 2） |
| 连续帧数 | 连续多少帧确认才记事件 |
| 冷却秒数 | 同一路多久内不重复刷事件 |

## 七、技术要点（给想深挖的同学）

1. **姿态**：COCO-17 关键点；库可选 Ultralytics YOLO-pose 或 rtmlib（RTMO/RTMPose 等）。  
2. **跟踪**：跨帧给人物分配 `trackId`，用于速度与持续卧地判断；摄像头与图片使用 **独立 sourceKey**，避免互串基线。  
3. **判定**：四指标加权得分 + `min_score`；视频/摄像头还有连续帧与冷却，抑制抖动误报。  
4. **合成框**：判定跌倒的人会合成 `className=fall` 检测框，供叠加与统计。  
5. **视频任务**：异步 job + 进度轮询 + 输出标注视频与稀疏事件列表。  

API 前缀大致为 `/api/ai/fall`（单帧 detect、视频任务等），页面已封装，日常演示不必手调接口。

## 八、适用场景与边界说明

**适合：**

- 养老院 / 居家看护演示  
- 病房、走廊等固定机位试点  
- 安防培训、算法效果对比  

**注意：**

- 严重遮挡、极远小目标、剧烈镜头抖动会降低关键点质量  
- 「坐着、躺着睡觉」与「跌倒」在姿态上可能接近，需靠速度、连续帧与业务复核区分  
- 本能力是 **视觉辅助告警**，不能替代人工值守与急救流程
