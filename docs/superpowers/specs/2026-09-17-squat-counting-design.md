# 健身蹲起计数生产场景设计

## 目标

在“生产模型场景”中新增“健身蹲起计数”场景，复用项目已有的人体姿态模型，通过上传视频、本地实时摄像头或项目已登记的网络摄像头视频流，对单一主训练者进行蹲起检测和计数。

上传视频生成可播放、可下载的标注视频和统计摘要。本地摄像头与网络摄像头提供实时标注、计数和会话摘要，但不录制完整视频。

## 范围与边界

- 仅统计一个主训练者，不进行多人独立计数。
- 主训练者优先选择人体框面积大且腿部关键点完整的人，并尽量延续上一帧目标。
- 一次有效动作必须完整经过“站立 → 下蹲到底 → 重新站立”。
- 半蹲、初始即处于蹲姿、起身未完成、关键点质量不足或目标丢失期间均不计数。
- 实时会话停止后只保留本次摘要，不保存本地或网络摄像头录像。
- 本功能复用姿态模型，不引入新的动作分类模型或训练流程。
- 首版不提供训练计划、卡路里估算、多人排名或云端历史报表。

## 方案选择

采用独立 `squat-counting` 生产场景，并复用现有 COCO-17 姿态模型。计数状态机位于独立业务服务，不写入通用姿态推理层。

没有选择扩展现有人体姿态工作台，因为通用关键点估计和有状态健身动作分析的输入、接口与生命周期明显不同。没有选择在浏览器内完成计数，因为浏览器逐帧请求无法可靠支持上传视频和网络摄像头，网络抖动也会破坏动作状态。

## 场景与模型

生产模型场景目录增加 `squat-counting` 分组，工作台类型为 `squat_counting`，模型选项复用当前人体姿态分组中的 COCO-17 模型：RTMO、RTMPose、YOLO-Master Pose、YOLO11 Pose 和 YOLO26 Pose。DWPose 的 133 点输出只有在能够稳定映射 COCO-17 腿部关键点时才允许选择。

默认优先选择已就绪的 `yolo11n-pose`；若该模型未就绪，则沿用场景现有的模型就绪逻辑，让用户选择其他已就绪姿态模型。姿态模型仍负责输出人体框、置信度和关键点，蹲起服务只消费统一后的关键点结构。

## 组件边界

### 蹲起分析器

无状态几何函数负责：关键点有效性检查、髋—膝—踝夹角计算、左右腿角度融合和主训练者候选评分。

有状态分析器负责：主目标延续、角度中值平滑、连续采样确认、动作阶段转换、计数、目标短暂丢失恢复和摘要累计。分析器接受一帧统一姿态结果与采集时间，返回当前主目标、原始/平滑角度、阶段、计数、跟踪状态和本帧是否完成一次动作。

### 视频任务

上传视频进入后台任务。任务逐帧运行姿态模型和同一个蹲起分析器，将骨架、膝角、阶段和累计次数绘制到输出帧，写出 MP4，并持续更新任务进度。完成后返回总次数、有效动作时间段、平均/最低膝角、有效分析时长、处理 FPS 和安全下载地址。

### 实时会话

实时会话拥有独立分析器实例、模型选择、参数、最近活动时间和冻结后的摘要。

- 本地摄像头由浏览器通过 `getUserMedia` 获取，按限制频率压缩为 JPEG 并上传。每帧携带单调递增序号和采集时间，服务端拒绝重复或乱序帧，响应中包含标注帧和实时状态。
- 网络摄像头由后端读取项目已登记并启用的视频源。后台线程执行姿态推理和分析，MJPEG 接口输出最近标注帧，状态接口输出计数与摘要。
- 停止、空闲超时、断流终止或异常退出均必须释放摄像头、后台线程和分析器资源。

### 前端工作台

新增 `SquatCountingWorkbench`，由 `ScenarioApp` 根据 `squat_counting` 工作台类型加载。工作台包含：

- 视频文件、本地摄像头、网络摄像头三个输入页签；
- 姿态置信度以及折叠的高级动作阈值；
- 原始或标注画面；
- 总次数、当前阶段、实时膝角、跟踪状态、有效时长和 FPS；
- 上传任务进度、完成摘要、标注视频播放与下载；
- 实时会话启动、停止和资源清理控制。

切换输入来源、切换模型或离开页面时，前端必须停止浏览器媒体轨道、帧发送、状态轮询和后端会话。

## 主训练者选择

候选人必须至少有一侧髋、膝、踝关键点达到置信度要求。候选评分综合人体框面积、有效腿部关键点数量与置信度。

已有主目标时，优先通过人体中心距离、框重叠率和人体尺度相似度延续目标，避免旁人经过时发生切换。主目标短暂丢失时保留跟踪与动作状态约 1 秒；超过保留窗口后取消未完成动作并允许重新锁定。重新锁定不会继承未完成动作，但保留已完成的累计次数。

## 蹲起状态机

### 角度

每侧膝角由髋、膝、踝三点计算。只有三个点均达到关键点置信度阈值时，该侧角度才有效；一侧有效时使用该侧，两侧均有效时取平均值。角度先经过短窗口中值滤波，再进入状态机。

默认参数：

- 站立阈值：膝角 `≥ 160°`；
- 下蹲阈值：膝角 `≤ 100°`；
- 站立与下蹲确认：连续 3 个有效采样；
- 主目标丢失宽限：1 秒。

站立阈值必须大于下蹲阈值，两阈值之间形成滞回区。阈值和确认采样数作为高级参数开放，并在前后端同时校验。

### 阶段

状态依次为：

1. `waiting_stand`：尚未确认初始站立；
2. `standing`：已确认站立，允许开始一次动作；
3. `descending`：进入过渡区并向下运动；
4. `bottom`：连续满足下蹲阈值；
5. `ascending`：离开下蹲区并向上运动；
6. 回到 `standing`：连续满足站立阈值后计数加一。

仅从已确认的 `standing` 出发、到达 `bottom`、再返回 `standing` 的完整周期计数。初始画面处于蹲姿时保持 `waiting_stand`，直到先完成一次站立确认；因此随后的完整动作才是第 1 次。

短暂缺少有效角度时冻结状态；在丢失宽限内恢复同一目标可继续动作。超过宽限时回到 `waiting_stand`，未完成周期作废。

## API 设计

所有接口沿用现有登录鉴权与生产场景权限边界。

### 上传视频

- `POST /api/ai/squat/video`：multipart 上传视频，字段包含 `file`、`modelId`、`conf` 和可选动作阈值，返回 `jobId`。
- `GET /api/ai/squat/video-progress/<jobId>`：返回任务状态、进度、当前计数、完成摘要和输出地址。
- `GET /api/ai/squat/output/<name>`：仅下载该功能生成且属于允许命名格式的 MP4。

### 实时会话

- `POST /api/ai/squat/sessions`：创建 `local` 或 `network` 会话。网络会话必须提供用户有权访问且已启用的 `cameraId`。
- `POST /api/ai/squat/sessions/<sessionId>/frames`：接收本地摄像头 JPEG 帧、帧序号和采集时间，返回标注图与实时状态。
- `GET /api/ai/squat/sessions/<sessionId>/stream`：仅供网络摄像头会话输出 MJPEG 标注流。
- `GET /api/ai/squat/sessions/<sessionId>`：返回计数、阶段、膝角、跟踪状态、有效时长、FPS 和终止原因。
- `DELETE /api/ai/squat/sessions/<sessionId>`：幂等停止会话，返回冻结后的最终摘要。

接口响应继续使用项目统一的 `code`、`message`、`data` 外壳。会话和任务必须按创建用户隔离。

## 输入限制与资源控制

- 上传文件只接受项目实际支持解码的视频扩展名，使用安全文件名并限制体积。
- 本地摄像头帧限制像素、JPEG 字节数和提交频率；超限请求不进入模型。
- 服务端为每个用户限制实时会话数量，并为会话设置空闲超时。
- 网络视频源只接受项目摄像头表中的记录，不允许客户端直接提交任意 RTSP URL。
- 网络断流只进行有限次数重连。重连期间冻结状态且不计数；重连失败后终止会话并保留摘要。
- 上传任务或实时会话异常时必须关闭视频句柄、临时输出和后台线程；未完成输出不能通过下载接口访问。

## 错误表现

模型类型错误、模型未就绪、视频格式或体积不合法、摄像头无权限、网络摄像头不可用、乱序帧、解码失败、推理失败和会话过期分别返回明确错误状态。前端显示可行动的错误信息，并保留异常前已完成的次数；恢复时不会补算缺失期间的动作。

目标存在但腿部关键点不足不是接口错误，返回 `insufficient_keypoints` 跟踪状态并冻结当前动作。画面中无人时返回 `no_person`。

## 测试设计

### 后端单元测试

- 三点膝角及退化坐标；
- 单腿有效、双腿融合和关键点置信度过滤；
- 面积与完整度评分、上一目标延续和旁人干扰；
- 完整蹲起只计一次；
- 半蹲、角度抖动、初始蹲姿、未完全站起不计数；
- 短暂丢失恢复和超时后取消未完成动作；
- 多次完整动作累计与摘要指标。

### 后端接口与任务测试

- 视频任务创建、进度、完成、失败和安全下载；
- 本地会话帧序号校验、状态累计、幂等停止和超时回收；
- 网络摄像头授权、后台读取、断流重连、MJPEG 输出和资源释放；
- 模型任务类型、阈值关系、文件大小、帧大小和会话归属校验。

测试以合成关键点序列验证计数确定性，模型和视频集成使用短小固定样例，不依赖真实摄像头。

### 前端测试与构建

- 三种来源的可运行条件、切换行为和校验消息；
- 上传任务轮询、完成摘要和输出链接；
- 本地摄像头轨道、帧发送和乱序响应保护；
- 网络会话流地址、状态轮询、停止与离开页面清理；
- 场景工作台映射与 API 文档状态；
- 执行前端状态测试和生产构建。

## 验收标准

- 用户可在生产模型场景中找到并打开“健身蹲起计数”。
- 三种输入方式均可选择已就绪的姿态模型运行。
- 标准“站立—深蹲—站立”序列稳定计为一次，抖动和半蹲不会重复或错误计数。
- 多人画面只跟踪单一主训练者，旁人经过不会轻易切换目标。
- 上传视频可获得标注 MP4 和摘要；实时来源停止后获得摘要且无录像文件。
- 页面退出、任务失败、摄像头断流和会话超时后没有遗留媒体轨道、视频句柄或工作线程。
- 新增后端测试、前端状态测试与生产构建通过，原有模型场景测试无回归。
