# 模型生产场景第一阶段设计（1—9）

## 1. 背景与目标

项目已登记 90 个模型，并在 `docs/MODEL_USAGE_SCENARIOS.md` 中描述了每个模型的定位、生产场景、流程、产出、验收方式和风险。本阶段为前 9 个模型建立可操作的独立应用页面及对外 API，同时形成后续 81 个模型可沿用的场景框架。

本阶段交付目标：

- 每个模型拥有独立、可直接访问的应用路由，不以筛选条件模拟独立页面。
- 同类模型复用工作台能力，但页面内容、默认参数、项目说明、指标和 API 示例由模型场景独立配置。
- 已就绪模型能够调用真实推理链路；未就绪模型明确展示状态、原因和准备步骤，不生成虚假结果。
- 对外 API 使用现有开放平台的身份验证、授权、限流、审计和响应规范。
- 场景元数据与推理适配解耦，使后续阶段以注册配置为主、专用能力组件为辅。

## 3. 架构

### 3.1 场景注册表

后端建立唯一可信的场景注册表。每项至少包含：阶段、序号、模型 key、名称、业务分类、能力类型、生产项目、说明、流程、产出、验收指标、风险、默认参数、支持输入、内部入口和开放 API 路径。

运行时状态不写死在注册表中，而通过 `AiModel` 数据库记录和权重路径计算，统一返回：

- `registered`：场景和模型均已登记；
- `weights_ready`：权重路径存在；
- `runtime_ready`：运行库及适配器可用；
- `api_ready`：当前场景允许执行；
- `reason`：不可执行时的可操作原因。

前端场景配置由后端接口返回，避免前后端维护两份业务文案。前端只维护工作台类型到 Vue 组件的映射。

### 3.2 推理适配层

建立场景服务，将四类请求归一化后转交现有推理能力：

- `segmentation`：模型、图片、正/负点或矩形提示、阈值，返回 mask、面积、占比及叠加图信息。
- `vehicle_reid`：模型、查询车辆图和候选车辆图，返回归一化特征距离、相似度排序及匹配结论；跨镜完整流程继续与现有 MTMC 服务联动。
- `plate_detection`：模型、图片、置信度和图像尺寸，返回车牌框、置信度及可选 OCR 联动字段。
- `obb_detection`：模型、图片、置信度和图像尺寸，返回四点坐标、角度、类别和置信度。

适配层必须校验模型 key 与能力类型相符，并复用已有推理实现。只有现有能力无法表达时才增加窄范围适配器。

### 3.3 前端结构

新增场景总览页、场景外壳和四种工作台组件。独立路由指向同一场景外壳，并通过路由元信息锁定模型 key；用户不能通过查询参数把一个页面切换成另一个模型。

桌面布局：顶部为模型与生产项目状态带；主体为左侧操作参数、中央图像/轨迹画布、右侧结构化结果；底部呈现生产流程、验收指标、API 示例和风险边界。窄屏按“输入—运行—结果—说明”顺序纵向排列。

视觉采用工业视觉控制台语汇：深石墨、钢蓝、雾灰为基础，设备蓝表示运行，安全琥珀表示待处理，红色仅表示失败或风险。画布和数据链路作为视觉重点，装饰不得压过推理结果。

## 4. API 设计

### 4.1 管理端接口

- `GET /api/ai/model-scenarios?phase=1`：场景列表及动态就绪状态。
- `GET /api/ai/model-scenarios/<model_key>`：单个场景详情。
- `POST /api/ai/model-scenarios/<model_key>/infer`：管理端同步图片类推理入口。

列表和详情要求已登录并具备模型查询权限；推理要求模型推理权限。接口统一返回 `{code, message, data}`。

`infer` 使用 `multipart/form-data`：通用字段为 `file`；分割额外接受 `points`、`labels`、`box`（SAM 不使用且拒绝 `conf`）；检测接受 `conf`、`imgsz`；ReID 接受 `query` 和一个或多个 `gallery`。服务端以场景注册表决定允许字段，不接受客户端指定任意权重路径或运行库。POST 推理在读取 body/form/files 前强制校验正整数 `Content-Length`：缺失返回 411、格式错误或不大于零返回 400、超限返回 413；随后限制 40 个 part、33 个文件、单图 12 MiB、总文件 396 MiB 和 4000 万像素。GET 列表/详情无正文时允许 Content-Length 缺失或为零。

EfficientSAM 和 YOLO26n-P2 车牌制品必须在权重同目录提供 `production-manifest.json`。清单至少包含与注册场景一致的 `modelKey`、`task`，只含 basename 的 `artifactFile`，以及与制品精确匹配的 64 位十六进制 `artifactSha256`。EfficientSAM 可通过 `artifacts.fp32` / `artifacts.int8` 分别绑定同目录官方资产，至少发布一种精度，并以 `supportedPrecisions` 对外公开；推理只接受已发布精度并把对应文件传给适配器。P2 始终保持单制品规则，目录存在多个兼容权重即为歧义。清单缺失、路径穿越、制品错绑或 hash 不匹配时均为 not ready；readiness 与 inference 共用这一无导入、无加载、无写入的契约。P2 清单另需 `trainingComplete: true` 和车牌类别。

### 4.2 对外接口

- `GET /openapi/v1/model-scenarios`：返回调用方获授权的场景目录。
- `GET /openapi/v1/model-scenarios/<model_key>`：返回场景能力、状态和参数规范。
- `POST /openapi/v1/model-scenarios/<model_key>/infer`：执行单次场景推理。

对外接口复用 `OpenApp` 鉴权签名、时间戳/随机数防重放、应用状态、IP 白名单、权限 scope、速率和日配额、请求日志。新增 scope `model-scenario:read` 与 `model-scenario:infer`。响应沿用开放 API 的 request id 和错误码约定。

对于以下情形必须返回明确的 4xx 状态：未知模型 key、场景未开放、模型未启用、权重未就绪、输入字段错误、文件类型或大小超限。运行库加载或推理异常返回受控 5xx，不暴露绝对路径或堆栈。

## 5. 页面功能

### 5.1 场景总览

- 按能力和就绪状态筛选，按序号或名称搜索。
- 显示第一阶段进度、四类能力分布和每个场景的四级就绪状态。
- 卡片展示真实生产项目、输入类型、核心产出和模型 key。
- 点击卡片进入对应独立应用；未就绪场景仍可进入并查看准备步骤。

### 5.2 公共能力

- 拖拽/选择文件，显示格式和大小限制、输入预览、清除与重新选择。
- 参数提供业务化说明、合法范围、恢复默认值。
- 运行期间禁止重复提交，展示阶段、耗时和失败原因。
- 结果支持复制 JSON 和下载 JSON；有可视化输出时支持下载叠加图。
- API 面板按当前模型生成 curl 示例、字段说明与响应示例，密钥使用占位符。
- 就绪状态、风险边界和验收指标在运行前可见。

### 5.3 专用能力

交互分割支持在图上添加正点、负点和矩形提示，撤销/清空提示，展示 mask、面积占比和交互次数。若底层模型只支持部分提示方式，页面按能力声明禁用不支持的控件。

车辆 ReID 支持查询图和多候选图，提供相似度阈值、候选排序、匹配/拒识结果和可用于跨镜串联的结构化输出。完整视频 MTMC 通过现有页面联动，不在本阶段复制一套视频编排器。

车牌检测支持阈值与尺寸参数、车牌框叠加、裁剪预览、检测结果表和 OCR 联动状态。定位模型不会把检测框冒充为字符识别结果。

OBB 支持旋转四点框叠加、角度和坐标表、选中目标裁剪/透视预览及结果导出。

## 6. 数据流与安全

浏览器先获取场景详情和动态状态；只有 `api_ready=true` 时允许提交。服务端再次进行身份、scope、模型、状态、权重、文件和参数校验，随后调用能力适配器。输出先归一化为场景结果结构，再由管理端或开放 API 包装返回。

上传文件使用安全文件名或内存流处理，限制类型与大小，不接受远程 URL，不允许调用方提供文件系统路径。日志记录应用、模型 key、能力、耗时、响应码和 request id，不记录图片二进制、密钥或完整个人识别信息。

## 7. 错误与空状态

- 未登记：提示场景不存在，并返回场景总览。
- 已登记但未就绪：展示缺失层级、准备建议和接口文档，运行按钮禁用。
- 输入错误：在对应控件附近说明合法值，保留其他输入。
- 推理失败：保留输入和参数以便重试，展示 request id，不显示内部堆栈。
- 无检测/无匹配：作为正常空结果展示，并建议调整阈值或输入质量，不当作系统错误。

## 8. 测试与验收

后端采用测试先行，覆盖：

- 注册表恰好包含第一阶段 9 个唯一模型 key、正确序号和工作台类型。
- 列表/详情权限、未知 key、动态就绪状态。
- 四类请求的字段校验、模型能力匹配和归一化响应。
- 未启用、缺权重、运行库不可用等失败状态。
- 开放 API 的 scope、签名、IP、限流/配额和审计集成。
- 文件扩展名、大小、参数边界和敏感错误信息清理。

前端覆盖可抽离的场景选择逻辑和参数序列化，并以构建验证所有独立路由和异步组件可解析。人工验收九个 URL 的页面身份、桌面/窄屏布局、键盘焦点、空态、未就绪态、运行态、成功态、失败态、JSON 导出和 API 示例。

## 9. 非目标与后续阶段

本阶段不下载缺失权重、不承诺所有登记模型已生产就绪、不新建完整 MTMC 编排器、不改造现有通用检测页面，也不提前实现第 10—90 个模型。第一阶段注册表和工作台映射必须允许后续阶段追加配置，避免修改已发布 URL 和 API 契约。
